# 专利实验与附图复现

本文对应《一种电生理数据无损压缩及按需读取方法》的四幅附图。`main` 分支只保留生产库、使用示例和测试；本 `patent` 分支在相同生产代码基础上保存实验程序、测量记录、绘图程序和交底书。所有实验入口均在本目录，不需要其他仓库的源码。

## 1. 复现范围与版本

有两种复现方式：

1. **重绘已交付附图**：使用 `data/` 中保存的历史实测值。无需原始记录、GPU 或重新分选，可恢复图 1—4 的内容。
2. **从原始采样重新实验**：使用本分支的正式 v3 实现和配置化脚本重新压缩、校验、测量与分选，结果写入 `runs/`。这些是新测量，不覆盖原始证据，也不保证与历史秒数逐位一致。

历史图 3 测于 2026 年 11 月 10 日：本发明方法采用实验原型容器，其 rANS 块码流与正式 v3 相同，但容器索引、写入调度及解码工作区管理不同。图 4 的原始输入和 rANS 输入测于 11 月 11 日，使用当时的正式 0.3.0 读取器；mtscomp 是同日补充完成的三次对照。当前分支已经清除旧容器和旧后端，**不会假装用清理后的脚本重新取得了历史秒数**。源码/扩展文件指纹、原始任务配置、环境和审计结果保存在 `data/`，用于追溯当时测量。

生产代码基线为 `1eca837`。正式 v3 块格式保持不变，清理后的实现已对现有 30 分钟生产存档完成全量逐值和 SHA256 校验。旧实验原型的源文件不再作为可执行依赖随仓库分发。

## 2. 数据是什么，如何取得

图 3 和图 4 使用同一段 **Neuropixels 1.0 AP 连续记录的前 30 分钟**，不是多个数据集的平均值。

- 文件：无头二进制，小端有符号 `int16`，时间优先，连续存放全部 384 个通道。
- 采样率：30000 Hz；区间：`[0, 54000000)` 个时间采样点；时长：1800 秒。
- 形状：`54000000 × 384`；大小：`41472000000` 字节。
- 原始字节 SHA256：`b3f6ffaf23681be08af594a485aad7809aa2e7c37a5befb78656b2a436425499`。
- 当前机器上的截取文件：`F:/EphyPress_benchmarks/bandwidth_30min_20261103/first30min.dat`。
- 原完整记录及截取信息：`config/dataset.json`。来自 Open Ephys 的 `Neuropix-PXI-100.ProbeB-AP/continuous.dat`，原文件大小 `194905912320` 字节。
- 探针通道映射与几何：`config/probe.json`；完整分选必须使用这份配置。

原始记录属于本地实验数据，**仓库不包含该 41.472 GB 文件，也没有已确认的公开下载地址**。复现实测需自行取得同一记录；仅凭“30 分钟 Neuropixels”不能识别同一输入。其他数据只能用于方法验证，不能标作原图结果。

如持有原完整 `continuous.dat`，按二进制原样复制前 `41472000000` 字节即可；不做去均值、滤波、重排、幅值缩放或通道剔除。复制后必须通过 `validate` 的大小和 SHA256 检查。已经持有 `first30min.dat` 时无需再次截取。

## 3. 环境与安装

历史测量环境为 Windows 10、Python 3.11.14、NumPy 1.26.4、mtscomp 1.0.2、Kilosort 4.1.7、PyTorch 2.9.1+cu128；CPU 为 Intel Core Ultra 7 270K Plus（24 核），GPU 为 RTX 5090，驱动 610.88。输入/输出位于 KIOXIA SSD。完整机器信息和包版本见 `data/codec_evidence/`、`data/ks4_v03/environment.json` 与 `data/ks4_mtscomp/environment.json`。

从仓库根目录执行（激活虚拟环境的方式按操作系统选择）：

```powershell
git switch patent
python -m venv .venv-patent
.\.venv-patent\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e .
python -m pip install -r patent/requirements.txt
```

源代码安装需要 C++17 编译器；Windows 使用 MSVC Build Tools。依赖均从包管理器安装，不复制其源码。完整分选需要兼容 CUDA 的 GPU；仅重绘时可只安装 `numpy==1.26.4 matplotlib==3.10.7`。文档重建另外需要 python-docx 和 Pandoc，Word 导出脚本需要已安装的 Microsoft Word、pywin32 与 PyMuPDF。

历史编码/解码测量要求足够内存预读压缩文件；脚本检查可用内存大于压缩文件总大小加 4 GiB。正式分选读取器的 64 块缓存本身约占 2.95 GB，另有预取、解码工作区和 KS4 内存。确保新实验输出盘有足够空间容纳约 15 GB 的 `.ep`、约 19 GB 的 `.cbin/.ch` 和九次分选结果。

## 5. 配置新实验

```powershell
Copy-Item patent/config.example.json patent/config.local.json
```

编辑 `config.local.json`：

- `raw`：原始 30 分钟数据路径。
- `archive`、`mtscomp`：要新建的 `.ep` 和 `.cbin`；mtscomp 的 `.ch` 与 `.cbin` 同目录同名。
- `probe`：探针 JSON；`output`：本次实验的独立输出目录。相对路径都相对于配置文件所在目录。
- `samples/channels/fs/sha256`：数据形状、采样率及原始字节指纹，复现原数据时不要修改。
- `block_samples=60000`：两秒存储块，各方法边界相同。
- `codec_workers=8`、`codec_cpus=[0,1,10,11,12,13,22,23]`：历史图 3 使用的八个独立物理性能核；`decode_repeats=5`。
- `sorting_cpus=[0,...,23]`、`numeric_threads=8`：历史图 4 的 CPU 范围及 Torch/BLAS 等数值线程限制。
- `batch_samples=60000`、`seed=1`：KS4 批次长度和随机/聚类初始化种子。
- `cache_blocks=64`、`prefetch_blocks=32`：EphyPress 分选读取器参数。mtscomp 使用上游切片读取，`n_threads=8`、`cache_size=10`。
- `rates_MB_s=[100,500,5000]`：十进制 MB/s；`sorting_order` 明确列出九次运行顺序。

CPU 编号只对原机器有意义。换机器时按实际拓扑选取八个不同物理核并更新配置，不能把“逻辑编号相同”当作“核类型相同”。实验脚本不会自动放宽亲和性要求。更换硬件、数据、线程数、块长或 KS4 设置后，应将结果表述为新的实验条件。

## 6. 从原始数据重新运行

```powershell
python patent/reproduce.py patent/config.local.json validate
python patent/reproduce.py patent/config.local.json encode
python patent/reproduce.py patent/config.local.json codec
python patent/reproduce.py patent/config.local.json preflight
python patent/reproduce.py patent/config.local.json ks4
```

也可对新的输出目录使用 `all` 顺序执行。每个测量任务在全新进程中串行运行；失败时保留 `job.json` 和 `run.log`，不伪造结果，也不覆盖已有成功结果。修正问题后可以直接用对应 worker 执行失败的 `job.json`，或换新输出目录重新实验。

各阶段行为：

1. `validate` 检查原始大小、全量 SHA256、探针文件和配置，保存环境及源码指纹。后续阶段要求同一份配置，不允许校验后修改输入文件。
2. `encode` 分别压缩一次，记录包括写入、哈希和 `fsync` 的整体编码时间。EphyPress 固定一阶模差分和单模型四路 rANS（尺度 14 位，逃逸符号 1024）；mtscomp 固定 zlib 默认级别 `-1`、时间差分开启、空间差分关闭、F 顺序。编码不是孤立熵编码内核的计时。
3. `codec` 先对两种压缩结果分别进行全量原始字节比较及 SHA256 校验，然后各执行五次 8 线程与五次 8 进程解码。每次在计时外顺序预读压缩文件，采用新读取器，不复用已解码样本。线程路径每批最多八块，计时包含线程池与读取器的构造/关闭；进程路径各处理连续块区间，只返回字节计数，不汇合完整数组，进程启动、依赖导入、扩展初始化和退出不计时。吞吐分母按完整原始采样字节数计算，无原始数据磁盘写出。
4. `preflight` 对原始、rANS 和 mtscomp 三种输入检查跨块、步进、尾部窗口以及 KS4 自身的带上下文批次；同时验证计费字节和缓存命中不重复收费。预检读取器随后关闭，不复用到正式分选。
5. `ks4` 在每次完整分选前预读输入文件、预热 GPU，然后以新读取器运行 KS4 公共接口。三种输入采用同一探针、采样率、通道数、批次、种子和数值线程数，`save_preprocessed_copy=False`。计时从调用公共接口开始，到结果导出及 CUDA 同步结束；首次压缩、导入、预热、文件预读、读取器构造及关闭均不计时。保留有效设置、完整日志、分选输出、输入字节计数和关闭后的计数，避免漏掉尾部预取。

脚本的读取限速是**应用层逻辑输入字节交付上限**，全部读取线程共享预算：原始路径按连续请求范围收费；rANS 按实际压缩载荷的 `readinto` 收费；mtscomp 按 `read_chunk` 使用的实际载荷读取收费。操作系统缓存命中仍计费，解码缓存命中不计费。输出写入不受该输入预算限制。**这不是实体慢速硬盘的直接实测**；图 4 说明所设输入带宽条件下完整读取实现的表现，不能单独归因于熵编码，也不能当作三者解码线程/缓存资源完全相同的对照。

原图每个带宽—方法组合只有一次完整分选，不能估计置信区间。分选单位数、标签不同不作为分选质量优势的证据。

## 9. 证据与清理后验证

- `data/codec_comparison.json`：图 3 使用的汇总及重复值；`data/codec_evidence/`：协议、环境、原始任务结果和审计。
- `data/ks4_v03/`：原始/rANS 六次完整分选；`data/ks4_mtscomp/`：配置匹配后的三次 mtscomp 分选。此前中止的非匹配实验未纳入。
- `data/ks4_three_inputs.csv`：九点曲线汇总；各任务 `effective_settings.json` 可核对实际 KS4 设置。
- `evidence_sha256.json`：上述证据及数据/探针配置的文件哈希。`verify_evidence.py` 检查文件完整性、原始数据身份、解码次数和分选点集合。
- `data/cleanup_validation.json`：本次整理的本地验证记录。包括生产库测试、独立 wheel 安装测试、真实记录全量无损校验，以及新实验入口的小规模冒烟检查。

本次整理没有重新执行九次 30 分钟数据的完整 GPU 分选。历史数字保留原始归属；新脚本的冒烟结果只证明入口、完整字节恢复、批次和计量路径可运行，不作为性能数据写入附图。
