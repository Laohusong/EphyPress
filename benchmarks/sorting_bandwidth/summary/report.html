EphyPress: KS4 and ChronoSort bandwidth benchmark

First 30 minutes of ProbeB-AP; 30 kHz, 384 channels, int16. One run per point. Windows 10 / RTX 5090; EphyPress 0.2.0; KS4 4.1.7. ChronoSort uses a 62000-sample valid core with 1768 context samples per side and a bounded cross-worker shared decode cache for compressed input.

All-data read/write measurements are not available for this ChronoSort configuration. Only the two input-read-limited curves are shown. Raw uses historical controls; the compressed curve comes from seven subsequent runs. These are not contemporaneous paired repetitions. The 60000-sample zero-context version is excluded.

The 28 KS4 points across both conditions come from a separate sweep. Original input values were verified exactly, but GPU clustering can change output counts; final arrays are not identical at every point.

Input-read limits apply only to original recording reads. All-data read/write limits use one shared read budget for original input and instrumented intermediates, plus a separate shared write budget; each direction uses the specified MB/s ceiling. This is application-level logical-byte delivery throttling, not a physical HDD test. OS file-cache hits are charged; decoded-cache hits and RAM reuse are not file reads. Imports, DLLs, filesystem metadata, and benchmark logs are excluded. Timing spans the public sorting API through final export and CUDA synchronization; initial CUDA setup and KS4 probe/reader construction are outside the timer.
